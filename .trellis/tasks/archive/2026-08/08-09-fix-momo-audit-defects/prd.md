# 修复 Momo 智能体审查缺陷

## Goal

修复已确认的工作流审计失真、DOE 数量未真实生效、工具轨迹不保真、生产占位能力伪成功、载荷文件未进入计算、请求参数静默宽松、预检和提交清单失败开放等缺陷，使运行结果、审计记录和实际副作用一致。

## Requirements

- 子任务按以下顺序实施：工作流完整性与 DOE；平台输入与生产安全；API 与交付门禁。
- 新工作流使用版本 `1.1.0`，不得改写历史冻结快照。
- 初始 DOE 默认 15、允许 5–24；精度不足每轮补 2 点，最多 2 轮。
- 工具参数及返回不得静默修正；必要规范化必须公开并可审计。
- Live 模式对未实现的独立计算能力失败关闭；Mock 模式允许演示但必须标明模拟。
- 不处理已证明正常的 CORS、历史消息预算、叙事 fallback、LEGACY 兼容测试和既有前端 lint 告警。

## Acceptance Criteria

- [x] 三个子任务的定向测试全部通过。
- [x] 后端完整测试、提交校验、Python 编译检查全部通过。
- [x] 前端类型检查、Vitest、lint 和生产构建通过，且无新增告警。
- [x] 审计轨迹能够区分干净成功与诊断完成，DOE 审批数量与真实设计数一致。
- [x] Live 模式不再持久化任何占位成功 Job 或 Artifact。
- [x] 上传的载荷文件以真实 Artifact ID 和内容进入执行链。

## Out of Scope

- 真实 ANSYS 全量长时间回归。
- 数据库迁移或历史工作流快照重写。
- 与本次审查无关的格式化、重构和告警清理。
