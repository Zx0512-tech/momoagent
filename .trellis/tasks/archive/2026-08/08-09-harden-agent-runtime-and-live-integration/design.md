# 技术设计

## 任务拆分与顺序

1. `08-09-fix-report-json-and-refresh-failure`：修改运行时代码并完成回归验证。
2. `08-09-plan-full-live-agent-integration`：在修复后的可靠性边界上交付完整真实流程路线图。

父任务只负责需求来源、顺序和最终集成验收，不承载第三套实现。

## 总体边界

- 当前代码改动限于报告 JSON 边界、终态刷新失败边界、测试和相应规范。
- 后续真实接入采用共享执行器：Agent 负责编排、审批和证据门禁；平台 Job 负责持久化、队列、取消与恢复；`pyansys_bridge` 负责数值算法和求解器适配。
- 现有原子 `REAL_*` 工作流在新分阶段执行链达到结果/制品对等前保留为回滚路径。

## 兼容性

- run 和 Artifact 只增加兼容字段，不迁移历史数据。
- 非有限浮点从非法 JSON 字面量变为 `null`，这是输出纠错；有限值及字段结构保持不变。
- 刷新失败 run 使用既有 `FAILED`、`currentStep=FAILED` 和结构化 `workflowGateError` 表达，不引入新终态。

## 回滚

- 运行安全修复可按单个实现提交回滚。
- 后续真实流程每个阶段由 capability flag/registry 控制；验收失败时恢复 501 和前端禁用，不恢复占位成功。
