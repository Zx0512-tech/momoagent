# 发布智能体共享站点（先行架构图）

## Goal

先交付一张可插入 Word 的整体功能架构图，清晰说明 MOMO 桥梁地震分析与阻尼器优化智能体的系统逻辑、主要功能模块与受控使用流程；站点发布后续再继续规划。

## Confirmed Facts

- 可发布对象位于 `momo_competition_submission/`，包含 React/Vite 前端和 FastAPI 后端。
- 完整的真实分析依赖 Windows x64、Python 3.13、OpenSeesPy 运行时和本地桥梁模型；智能体对话还需要用户自备兼容 OpenAI 接口的模型密钥。
- 前端支持 `VITE_API_MODE=mock`，可在没有后端的情况下提供完整的交互式模拟演示；README 明确规定该模式仅用于演示。
- 现有生产入口由 FastAPI 同源托管静态前端并提供本地 REST API，当前仓库没有 Sites 托管配置。
- 现有后端仅监听 `127.0.0.1:8000`，跨域访问也只允许本地开发地址；尚未实现面向终端用户的身份认证、用量控制或公网 HTTPS 入口。
- 因为前端与 API 由同一 FastAPI 服务提供，只要将整套服务放在同一台 Windows 主机上，无须拆分前后端，也无须为首版修改 CORS。
- 对话式智能体是前端主入口，平台还提供看板、荷载、命令流、求解批处理、结果、DOE、阻尼器、代理、优化和制品浏览等深挖入口。
- 真实工作流依次经历需求确定、荷载准备、环境预检、冻结审批、受控执行、结果提取、证据审查和报告；优化工作流额外包括基线、DOE、代理模型、主动学习、候选排序、Pareto/TOPSIS 推荐与独立 FEM 复核。
- 工作流通过预注册工具、前置条件、资源上限、审批和幂等键约束执行，并登记制品、日志和结果证据。

## Requirements

- 使用 Python/Matplotlib 生成可编辑文字的 SVG 架构图，并提供适配 Word 的高清 PNG 和 PDF。
- 图以“用户交互 → 智能体控制与安全门禁 → 真实有限元/优化计算 → 证据与结果回传”为主线，同时展示可用的功能模块。
- 图中文字使用中文，版面适配 Word 横向页面，阅读顺序清晰，避免过度技术细节和无法由现有实现佐证的功能宣称。
- 使用克制的工程蓝、青绿与暖色警示色；审批和证据门禁必须在图中显著可见。

## Acceptance Criteria

- [x] 输出一张信息完整的 SVG 架构图，文字在矢量查看器中可选择和编辑。
- [x] 同步输出 PDF 与至少 300 dpi PNG，插入 Word 后保持清晰。
- [x] 图中完整呈现用户入口、功能模块、受控真实计算流程以及审计证据闭环。
- [x] 图中明确显示“预检—审批—执行—证据审查”的安全门禁，且不出现密钥或虚构的运行能力。
