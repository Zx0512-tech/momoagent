# 技术设计

## 审计边界

本任务只读取产品代码、运行现有验证和增加任务内审计报告，不修改产品实现。审计对象是完整 `momo_competition_submission`，但工程数值正确性只检查软件证据链，不替代结构工程复核。

## 证据分层

1. **基线层**：运行现有测试、静态检查、生产构建、bundle budget 和提交包校验，记录命令、退出码与关键输出。
2. **契约层**：比较 Python/Pydantic Schema、工作流快照、API 响应与 TypeScript 类型，寻找同名异义、字段漂移、枚举漂移和静默规范化。
3. **状态层**：沿创建、审批、执行、取消、失败、恢复和结果追问路径追踪 run、job、tool call 与 artifact 的状态变化。
4. **边界层**：检查外部输入、文件路径、子进程、环境变量、日志、异常和资源限制的验证与传播。
5. **证据层**：抽样追踪 OpenSees/优化输入到最终制品、SHA256、门禁和 UI 呈现，确认结论不能脱离登记证据产生。

## 缺陷确认流程

每个候选问题依次通过：

1. 定位来源与消费者，确认真实运行路径可达。
2. 构造最小输入或测试，观察实际行为；不能运行时记录完整调用链。
3. 对照 README、Trellis 规范、公开 API 或测试所表达的预期行为。
4. 主动寻找反证，包括上游校验、可信内部数据、兼容分支和显式设计说明。
5. 只有反证不能消除问题时才写入缺陷清单，并按 PRD 严重度分级。

## 输出结构

`audit-report.md` 包含：

- 执行摘要与总体风险判断；
- P0–P2 已验证缺陷，按严重度和影响排序；
- P3 改进项；
- 已排除候选与排除依据；
- 基线命令与结果；
- 环境限制和未验证外部风险；
- 建议的修复批次，但不在本任务中实施。

## 风险控制

- 不运行真实外部 LLM、ANSYS 或联网依赖审计。
- 不启动会产生不可控工程计算的长任务；优先使用现有测试、归档证据和最小离线复现。
- 测试产生的临时文件仅限现有测试目录；审计结束检查 Git 状态，确保产品树无意外变更。
- 发现安全问题时不输出可直接滥用的敏感数据，只记录必要触发条件和修复方向。
