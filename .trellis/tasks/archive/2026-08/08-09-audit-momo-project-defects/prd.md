# 审计 MOMO 项目剩余缺陷

## Goal

对 `momo_competition_submission` 比赛提交包进行一次只读、证据驱动的系统缺陷审计，识别当前仍可复现或可由代码路径严格证明的缺陷，并给出严重度、影响、复现证据和最小修复建议，为后续逐项修复提供可信基线。

## Background

- 提交包由智能体后端、React 前端、OpenSees/优化核心、工程输入与证据、安装启动脚本和离线提交校验组成。
- 后端现有 30 个 pytest 文件，前端现有 Vitest、lint、TypeScript build 和 bundle budget；提交包另有 `verify_submission.py` 与 SHA256 清单校验。
- 最近两轮工作已修复 Harness 工作流、工具契约和参数保真问题，但尚未对整个提交包做一次统一缺陷审计。
- README 已明确记录三个前端高危依赖摘要尚未取得在线明细；本次只能核实仓库内可验证的状态，不把无法离线确认的 CVE 当作已证实缺陷。

## Requirements

### R1. 审计范围

审计覆盖以下边界：

1. 智能体工具目录、Schema、工作流授权、审批、幂等、参数保真、状态恢复和制品证据门禁。
2. FastAPI 接口、持久化、后台 Job、异常传播、输入验证、路径与进程调用边界。
3. React 前端与后端 API 类型/状态的跨层一致性，以及错误、空数据、等待、取消和未知状态分支。
4. OpenSees/优化核心的输入契约、失败传播、结果登记与最终证据校验链；不重新评审结构工程模型的学术正确性。
5. 安装、启动、依赖锁定、生产构建、提交清单和离线可复现性。

### R2. 证据标准

- 每个 P0–P2 缺陷必须包含精确 `file:line`、触发条件、实际行为、预期行为和影响。
- 可运行路径优先提供最小复现测试或命令；无法安全运行时必须给出完整静态调用链。
- 测试失败不自动等于产品缺陷，必须定位根因；代码气味不自动列为缺陷。
- 所有高优先级结论必须回读实际数据来源和信任边界，排除审查误报。

### R3. 严重度

- **P0 Critical**：可导致任意代码执行、凭据泄漏、不可恢复数据破坏或核心工程结论被静默篡改。
- **P1 High**：正常用户路径可稳定触发核心功能错误、权限/审批绕过或错误工程结果。
- **P2 Medium**：边界条件下出现错误、状态漂移、错误信息丢失或明显交付风险。
- **P3 Low**：不影响正确性的可维护性、描述或测试覆盖不足；与真实缺陷分开列出。

### R4. 输出

- 在任务目录生成 `audit-report.md`，按严重度排序记录已验证缺陷、排除项、验证结果和未能验证的外部风险。
- 最终回复先给出问题清单，再给总体结论；没有发现某类问题时也明确说明覆盖范围。
- 本任务不修改产品代码。修复应在用户确认优先级后创建独立任务，避免审计与修复相互污染。

## Acceptance Criteria

- [x] 记录后端 pytest、前端 test/lint/build/bundle、Python 静态检查和 `verify_submission.py` 的基线结果。
- [x] 完成工具/工作流单一事实源、公开 Schema、阶段参数、原始/实际参数和审批/幂等链路交叉检查。
- [x] 完成 API Schema、前端 TypeScript 类型、状态枚举和错误分支的跨层一致性检查。
- [x] 完成 Job/制品持久化、取消/恢复、文件路径、子进程和外部输入信任边界检查。
- [x] 完成 OpenSees/优化结果从输入、执行、登记到最终证据门禁的抽样追踪。
- [x] 每个 P0–P2 发现均满足 R2 证据标准，并至少经过一次独立的反证检查。
- [x] `audit-report.md` 区分已证实缺陷、P3 改进项、已排除误报和因环境限制未验证风险。
- [x] 审计过程不修改 `momo_competition_submission` 下的产品代码或生成物。

## Out of Scope

- 修改或修复审计发现的问题。
- 重新标定桥梁模型、重新论证阻尼器参数或给出正式工程设计结论。
- 依赖外部 ANSYS、真实 LLM 服务或互联网才能完成的验证。
- 未经授权运行在线 `npm audit`、升级依赖或调用外部服务。

## Technical Notes

- 项目定义以 `momo_competition_submission/README.md` 为准。
- 工具与工作流契约以 `.trellis/spec/backend/agent-harness.md` 和 `workflow-contract.md` 为审计基线。
- 本任务是复杂只读审计，使用 `design.md` 与 `implement.md`；当前为 inline 流程，不需要分派子智能体或填充 JSONL 上下文清单。
